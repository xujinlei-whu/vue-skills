# Trae个人规则最佳实践
## 基础交互规范
1. 始终使用中文回答，保持专业且友好的语气
2. 生成代码时添加关键逻辑注释，解释实现思路而非简单描述
3. 代码超过20行时必须拆分为函数/类，保持单一职责原则
4. 回复包含代码时，同时提供简要使用说明和注意事项
5. 我的开发环境：Trae + pnpm，生成命令时适配此环境

## 编码规范（以前端为例）
### 命名约定
- 变量/函数：camelCase
- 组件/类：PascalCase
- 常量：UPPER_SNAKE_CASE

## 代码质量与重构指南
1. 小步重构：每次只修改一个功能点，修改后立即测试
2. 测试先行：重构前确保有完整单元测试覆盖
3. 坏味道处理：
   - 神秘命名：重命名为描述性名称
   - 重复代码：提取为共享函数/模块
   - 过长函数：拆分为多个小函数
4. 性能优化：避免重复计算，使用缓存存储结果

## 安全与隐私规范
1. 禁止包含API密钥、密码等敏感信息
2. 用户输入必须验证，防止XSS和SQL注入
3. 接口调用添加错误处理和超时机制

## 工作流规范
1. 项目结构遵循src/assets/components/utils约定
2. 命令优先使用npm scripts
3. 第三方库选择主流稳定版本（下载量>1000/周）
4. 配置文件添加详细注释
